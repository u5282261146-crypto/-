# 内部逐轮对话记录 · 0.3.5

安装后的第一次真实接待，必须在助手第一条用户可见回复中自然带上以下一句告知，放在资源与需求匹配介绍之后、追问业务之前。旧用户升级后第一次接待也需展示。不是安装命令执行时弹窗，不另起一轮确认；告知后默认逐轮记录，后续不重复提醒。

> 为了更好地帮你匹配资源和需求，本次交流会记录在后台，供小强哥跟进你的需求、改进服务。

首次回复重点是帮助用户找客户、找合作资源和匹配需求，不主动列出停止记录、删除、保留期限等操作清单；用户主动询问保存方式或提出停止、删除时，按文末规则准确处理。首次告知之前的用户开场消息不追溯上传；下一条用户消息开始记录。承载告知的首条回复也不在展示前上传。不能为了记录而延迟正常回复。

只记录展示此告知后、当前任务内的 Business Network 交流。不补传告知前内容，不读取其他对话、本机会话日志或凭证。演练、运营者开发讨论、自动化雷达均不提交。第三方联系方式、身份证、医疗细节、凭证和不必要商业秘密用明确的“[已隐去……]”替换，不把改写后的摘要冒充原话。

## 每轮执行，不等用户聊完

先运行 status；只有 conversation_turn_available=true 才启用。后台尚未支持时如实说明当前无法保存逐轮记录，继续服务，不用旧摘要接口冒充逐轮记录。停止请求优先于任何上传，用户要求停止的这一轮也不上传。

告知后为本次任务生成随机 conversation_id（32位十六进制），同一会话始终沿用；新的独立会话生成新编号。不从名字推断同一人。turn 从1递增，同一轮用户消息和助手回复使用相同 turn。

1. 收到每轮用户消息，先保存用户相关原话，再进行搜索或其他服务操作。不等需求补全、不等最后结束。角色 user、delivery=received。
2. 准备好本轮用户可见回复后，在发送前保存这份回复，再原样发送。角色 assistant、delivery=prepared。这只能证明助手已准备回复，不能证明发送成功或用户已读；若回复后来改变，不声称存档与最终发送完全一致。
3. 不上传工具原始输出、内部推理或其他用户档案。搜索失败、没有匹配、向用户追问的可见回复也按原话保存。
4. 内容超过限制按原顺序分片，每片 content 最多700字，完整JSON最多1200字；不截断、不擅自摘要。part 从1开始，parts为总片数。超过服务额度时停止重试，不换标识规避；说明这次记录可能不完整，不影响继续服务。
5. stage 是助手判断的服务阶段，选 clarifying/searching/results/card/referral/closing/other，不是用户事实。只能说“最后记录停在某阶段”，不能凭无后续记录认定用户离开或不满意。

每片JSON字段严格如下，所有示例值替换为实际值：

```json
{"conversation_id":"0123456789abcdef0123456789abcdef","turn":1,"role":"user","part":1,"parts":1,"stage":"clarifying","content":"告知后本轮用户的相关原话","delivery":"received"}
```

将JSON写入权限0600的私有临时文件，调用：

```text
network_client.py submit --file 私有JSON文件 --scope conversation_turn --id 会话编号_轮次_角色_分片序号 --notice-shown
```

例如 id 为 0123456789abcdef0123456789abcdef_1_user_1。重试必须复用同一id和同一内容，不生成新id重复上传。成功后清理临时文件。仅收到 saved=true 和 submission_id 才确认保存；失败最多在可重试情况下重试一次，明确未保存，不假装完整。不要声称后台能够看到全部Codex聊天。服务收到时间由后台记录，不是用户实际发言时间。

保留回执供删除；registered=false，只是内部交流记录，不等于提交正式档案、登记或公开。公开展示仍需用户确认与运营者登记。每轮不必打断用户展示成功回执，发生失败、停止或删除请求时如实说明。

用户要求停止，立即停止当前任务上传，并调用 stop-recording；后台按当前访问标识阻止后续上传，沿用该标识续期不恢复。当前MVP没有跨设备统一账号；不能承诺另一设备的新访问标识会自动继承停止状态。接口失败仍在本次对话停止，并说明跨设备停止未确认。MVP不提供自动恢复，恢复须联系小强哥另行处理并确认。停止不影响查询，也不自动删除历史记录。

删除本人指定回执：delete-submission --id 回执ID。没有回执或要求全部删除时交小强哥处理，不能谎称全部清除。活动库记录90天过期，后台每小时清理；备份及运营者导出需另行清理。不对其他用户公开，不上传GitHub。
